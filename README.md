# SeatSure

ระบบจองคอร์สเรียนเสริมขนาดเล็ก ใช้เป็นระบบตัวอย่างสำหรับสาธิตแผน QA
ภายใต้คำสัญญาข้อเดียว: **"จ่ายแล้วต้องได้ที่นั่ง ไม่เกิน ไม่ซ้ำ ไม่หลุด"**

| คำสัญญา | ความเสี่ยง | สิ่งที่ป้องกัน |
|---|---|---|
| ไม่เกิน | R1 จองเกินจำนวนที่รับ | `book_seat` ล็อกแถวของคอร์สก่อนนับที่นั่ง |
| ไม่ซ้ำ | R2 จองซ้ำ หรือเก็บเงินซ้ำ | unique index ของการจอง และ idempotency key ของการจ่าย |
| ไม่หลุด | R2 จ่ายแล้วไม่ได้ที่นั่ง | `pay_booking` ยืนยันที่นั่งพร้อมกับรับเงิน ถ้าที่นั่งหมดจะบันทึกว่าต้องคืนเงิน |

สร้างด้วย React + Supabase หน้าเว็บใช้คอมโพเนนต์ของ [shadcn/ui](https://ui.shadcn.com) บน Tailwind CSS
การชำระเงินเป็นการจำลอง ไม่มีการตัดเงินจริง

## สิ่งที่ต้องมี

- Node.js 20 ขึ้นไป
- Docker Desktop (เปิดไว้)
- [Supabase CLI](https://supabase.com/docs/guides/cli)

## เริ่มใช้งาน

```
task up
```

`task up` เปิด Supabase ในเครื่อง สร้างไฟล์ `.env.local` และสร้างบัญชีกับคอร์สตัวอย่าง
ครั้งแรกใช้เวลาหลายนาทีเพราะต้องดาวน์โหลด Docker image
จากนั้นเปิด http://localhost:5173

บัญชีทดลอง รหัสผ่าน `seatsure123` ทุกบัญชี

| บทบาท | อีเมล | ทำอะไรได้ |
|---|---|---|
| ผู้ปกครอง/นักเรียน | `parent1@seatsure.test` ถึง `parent10@seatsure.test` (10 บัญชี) | ดูคอร์ส จอง จ่ายเงิน ดูใบเสร็จ |
| ครูผู้สอน | `teacher1@seatsure.test`, `teacher2@seatsure.test` | ดูรายชื่อผู้เรียนของคอร์สที่ตัวเองสอน |
| แอดมินโรงเรียน | `admin@seatsure.test` | เพิ่มคอร์ส กำหนดจำนวนรับ ปิดรับสมัคร ตรวจการชำระเงิน |

## สาธิตเทส

ชุดเทสเดียวกันรันได้สองโหมด เทสยิงคำขอเข้าฐานข้อมูลจริงผ่าน API เดียวกับที่หน้าเว็บใช้

```
task test:integration             # โหมดปกติ: ผ่านทั้ง 24 ข้อ
(cd apps/frontend && npm run test:unsafe)  # โหมดที่ปิดการป้องกัน: ไม่ผ่าน 5 ข้อ
```

โหมด unsafe สลับ `book_seat` และ `pay_booking` ไปใช้โค้ดแบบ "เช็กก่อนแล้วค่อยบันทึก" ที่ไม่มีการล็อก
เทสที่ไม่ผ่านคือ

| เทส | สิ่งที่เกิดขึ้นในโหมด unsafe |
|---|---|
| 20 คนกดจองที่นั่งสุดท้ายพร้อมกัน | คอร์สรับ 1 คน แต่จองสำเร็จประมาณ 10 คน |
| 25 คนแย่ง 5 ที่นั่งพร้อมกัน | จองสำเร็จเกิน 5 คน |
| จ่ายแล้วกลับมาจ่ายอีกรอบ | ถูกเก็บเงิน 2 ครั้ง |
| จ่ายหลังหมดเวลา แต่ที่นั่งยังว่าง | รับเงินแล้ว แต่การจองไม่ถูกยืนยัน |
| จ่ายหลังหมดเวลา และที่นั่งถูกคนอื่นจองไปแล้ว | รับเงินแล้ว ไม่มีที่นั่ง และไม่มีบันทึกว่าต้องคืนเงิน |

ระหว่างรันเทส ระบบจะหน่วง 100 มิลลิวินาทีระหว่าง "เช็กที่นั่ง" กับ "บันทึกการจอง" ทั้งสองโหมดเท่ากัน
เพื่อให้คำขอที่ยิงพร้อมกันซ้อนทับกันทุกครั้ง ถ้าไม่หน่วง บั๊กจองเกินยังเกิดได้แต่ไม่ทุกรอบ
ค่านี้เป็น 0 เมื่อใช้งานผ่านหน้าเว็บ (ตั้งใน `apps/frontend/tests/integration/global-setup.ts`)

เมื่อรันจบ ระบบจะกลับเป็นโหมดปกติและลบข้อมูลที่เทสสร้างไว้
ถ้าหน้าเว็บขึ้นแถบแดง "โหมดสาธิตบั๊กเปิดอยู่" ให้เข้าเป็นแอดมินแล้วกด "กลับเป็นโหมดปกติ"

| `src/pages/` | หน้าเว็บ React หนึ่งไฟล์ต่อหนึ่งหน้า |
| `src/components/` | คอมโพเนนต์ที่หน้าต่าง ๆ ใช้ร่วมกัน เช่น โครงหน้า (`app-shell`) ป้ายสถานะ แถบที่นั่ง |
| `src/components/ui/` | คอมโพเนนต์ของ shadcn/ui (ปุ่ม การ์ด ตาราง ไดอะล็อก ฯลฯ) |

## แก้หน้าตา

- เปลี่ยนสีหรือความโค้งมุมทั้งแอป: แก้ตัวแปรใน `:root` ของ `src/index.css` (เช่น `--primary`, `--radius`)
- เพิ่มคอมโพเนนต์ของ shadcn/ui: `npx shadcn@latest add <ชื่อ>` ไฟล์จะมาอยู่ใน `src/components/ui/`
- import ภายในโปรเจกต์ใช้ `@/` แทน `src/` เช่น `@/components/ui/button`

## ใช้งานผ่านอินเทอร์เน็ต

หน้าเว็บอยู่บน Cloudflare Workers ส่วนฐานข้อมูลและระบบล็อกอินอยู่บน Supabase Cloud
ค่าเชื่อมต่อของโปรเจกต์คลาวด์อยู่ใน `.env.production.local` (ไม่เก็บใน git)

ตั้งค่าครั้งแรก:

```
supabase login
supabase link --project-ref <รหัสโปรเจกต์ Supabase>
supabase db push
(cd apps/backend && npm run cloud:seed)
npx wrangler login
(cd apps/frontend && npm run deploy)
```

- `npm run cloud:seed` (ใน `apps/backend`) ต้องมี `SUPABASE_SERVICE_ROLE_KEY` (secret key ของโปรเจกต์) และ `SEED_PASSWORD` ใน `.env.production.local` ก่อน
- บัญชีบนคลาวด์ใช้รหัสผ่านจาก `SEED_PASSWORD` ไม่ใช่ `seatsure123` และหน้าเข้าสู่ระบบบนเว็บจริงไม่มีปุ่มบัญชีทดลอง
- แก้หน้าเว็บแล้วสั่ง `npm run deploy` แก้ schema แล้วสั่ง `supabase db push`
- `task up` และ `task test` ใช้ Supabase ในเครื่องเสมอ ไม่แตะโปรเจกต์คลาวด์
