React 19, Vite, Tailwind v4 and shadcn/ui (radix-nova), with Thai UI text. It talks only to the backend API; see
[Architecture](/architecture) for the layer table and import rules.

## Layers in practice

| Where | What |
|---|---|
| `src/entities/` | domain types and pure rules (course, booking, my booking, roster, profile, `DomainError`); `Booking` re-exports the contract DTO |
| `src/interfaces/` | gateway ports such as `AuthGateway` |
| `src/use-cases/` | one factory per action (`createSignIn`, `createLoadMyBookings`, ...), gateway passed in |
| `src/adaptor/http/` | `client.ts` (middleware), `session-store.ts`, and one `<area>-gateway.ts` per port |
| `src/app/deps.ts` | composition root: wires gateways into use cases; pages import use cases from here |
| `src/pages/`, `src/components/` | pages and feature components (older layout, move into layers when touched) |

Use cases throw `DomainError(code)`; the UI maps codes to Thai messages (`src/lib/format.ts`). A port exists only if there
is a second implementation (a fake for tests) or the contract may change.

## The HTTP adaptor

- `client.ts` is the only code that calls `fetch`. It adds the bearer token, refreshes once on a 401, shares one refresh
  between parallel requests, times out after 15 s and converts failures to `DomainError`. Details in [Authentication](/authentication).
- `session-store.ts` keeps the tokens in `localStorage`, shared across tabs.
- A gateway implements a port over the client: `client.request<Type>('GET', '/me')`. Types come from `@contract`.
- The base URL is `VITE_API_URL`. Only the dev server falls back to `http://localhost:3001`; a production build without it throws at startup (`resolveApiBase` in `adaptor/http/client.ts`). It is the only variable the browser bundle reads.
- There is no Supabase client in the frontend: `@supabase/*` is not a dependency and `layering.test.ts` fails on any such
  import under `src/`. Never put a service key in anything bundled.

## Auto-refresh

Pages call `useAutoRefresh(load)` (`src/lib/use-auto-refresh.ts`): the data reloads every 15 s and when the tab becomes
visible again. There is no Realtime subscription, so another user's change shows up within about 15 s.

## shadcn/ui only

- Build every screen from the components in `src/components/ui/`. Do not hand-roll a button, input, dialog, table,
  select, badge or card.
- Missing a primitive? `npx shadcn@latest add <name>`. Do not write a lookalike.
- Feature components (`src/components/<feature>/`) wrap `ui/*`; they never restyle or copy it. Edit a `ui/*` file only to
  change the design system for the whole app.
- Theme tokens live in `src/index.css`. No inline hex colors and no other UI library. Icons from `lucide-react`, toasts
  from `sonner` through `ui/sonner`.

## Styling goes through CVA, never inline in TSX

A component file reads as structure, not a wall of utility classes ([CVA docs](https://cva.style/)).

- No Tailwind class strings in `.tsx`: no `className="flex gap-2"`, no `cn('...')`, no class maps, no `style={{}}`.
- Every class string lives in a sibling `<name>.styles.ts` built with `cva` (`class-variance-authority`). The TSX only
  calls it: `className={card({ tone })}`.
- Tone, size and state become cva `variants` with `defaultVariants`; booleans become variants, not ternaries on class strings.
- A static element with no variants is still a `cva('...')` so the TSX stays class-free.
- Export prop types with `VariantProps<typeof x>`.
- cva does not merge conflicting utilities (no `tailwind-merge`): do not pass a `className` that overrides a utility the
  style function already sets; add a variant.
- `ui/*` (shadcn) keeps its own inline `cva`.

```ts
// status-badge.styles.ts
export const badge = cva('', {
  variants: { tone: { ok: 'border-emerald-200 bg-emerald-50 text-emerald-700', muted: 'border-transparent bg-muted' } },
  defaultVariants: { tone: 'muted' },
})
```

```tsx
// status-badge.tsx
<Badge variant="outline" className={badge({ tone })}>{children}</Badge>
```

`apps/frontend/tests/unit/styles.test.ts` fails on a literal `className="..."`, `cn(` or `style={{` in any `.tsx` outside
`src/components/ui/`; `layering.test.ts` enforces the import rules.

## Theming and motion

- **Choices.** `light`, `dark` or `system` (default). `system` follows `prefers-color-scheme` and reacts when the OS
  changes. The choice is saved in `localStorage` under `seatsure-theme`; every access is wrapped in try/catch with an
  in-memory fallback (`src/lib/theme.ts`), so a private window still works for the page view.
- **How it is applied.** The `dark` class on `<html>` switches the `.dark` token set in `src/index.css`, and
  `color-scheme` makes native controls and scrollbars follow. A small inline script in `index.html` sets the class before
  React loads, so there is no flash. `ThemeProvider` and `useTheme()` live in `src/lib/theme-provider.tsx`;
  `ThemeToggle` (`src/components/theme-toggle.tsx`) sits in the app shell header and on the login page.
- **Add a themed component the CVA way.** Use semantic tokens first (`bg-card`, `text-muted-foreground`, `border-border`);
  they already switch with the theme. For a status colour that has no token, pair every raw colour with a `dark:` sibling
  in the same cva string: `bg-emerald-50 text-emerald-700 dark:bg-emerald-950 dark:text-emerald-300`.
  `tests/unit/dark-variants.test.ts` fails with the file and string when a pair is missing, and
  `tests/unit/contrast.test.ts` checks the token pairs against WCAG AA in both themes.
- **Motion.** Interactive states use `transition` with `duration-200 ease-out`; route content fades in with
  `animate-in fade-in-0 slide-in-from-bottom-2` (`tw-animate-css`). Every transition or animation you add also carries
  `motion-reduce:transition-none motion-reduce:duration-0` or `motion-reduce:animate-none`. `index.css` adds a
  `prefers-reduced-motion` safety net for the animations that ship with shadcn.
