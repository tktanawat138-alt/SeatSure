`docs/notes/` holds short, dated notes: what changed, why, the decisions made and the caveats. Guides in this site say
how things work now; a note records how and why they got that way, so the next reader does not have to rediscover it.

## When to write one

After any change that has no obvious home in a guide page: a decision, a workaround, a limitation, a follow-up. If a guide
page describes the changed behaviour, update the page too.

## Format

File name `docs/notes/YYYY-MM-DD-<topic>.md`. Suggested sections: **What**, **Why**, **Decisions**, **Caveats**.
Notes are append-only history: add a new note instead of rewriting an old one, unless the old one is wrong.
