## Login

A user signs in with email and password; the API signs in against Supabase Auth and the browser stores the session, then loads the profile.

```mermaid
sequenceDiagram
  autonumber
  actor U as User
  participant LP as LoginPage
  participant GW as auth-gateway
  participant C as client.ts
  participant S as session-store
  participant API as Express API
  participant AP as SupabaseAuthProvider
  participant GA as Supabase Auth
  participant DB as Postgres profiles
  participant AU as AuthProvider (lib/auth)

  U->>LP: submit email, password
  LP->>GW: signIn(email, password) via deps.ts
  GW->>S: clear() old session
  GW->>C: request POST /auth/login
  C->>API: POST /auth/login JSON email, password (no Authorization)
  API->>API: LoginBody.parse (email 1..254, password 1..200)
  API->>AP: auth.login -> provider.signIn
  AP->>GA: signInWithPassword (fresh anon client)
  alt credentials valid
    GA-->>AP: session
    AP-->>API: accessToken, refreshToken, expiresAt
    API-->>C: 200 success true, data Session, Cache-Control no-store
    C-->>GW: Session
    GW->>S: set(session) -> localStorage seatsure.session
    S-->>AU: listener fires with new token
    AU->>C: loadMe -> GET /me, Bearer accessToken
    C->>API: GET /me
    API->>AP: requireAuth -> verify(token) with service key
    AP->>GA: getUser(token)
    API->>DB: profile(id) select full_name, role
    API-->>C: 200 data id, email, fullName, role
    C-->>AU: CurrentUser
    AU-->>LP: App renders the home page for the role
  else wrong email or password
    GA-->>AP: 400
    AP-->>API: DomainError Invalid login credentials
    API-->>C: 401 message Invalid login credentials
    API->>API: accessLog writes login_failed with email_hash, ip
    C-->>LP: DomainError (no session, so no refresh)
    LP-->>U: errorText shows the Thai message
  else Supabase throttles
    GA-->>AP: 429
    API-->>C: 429 message rate_limited
  else body invalid
    API-->>C: 400 Validation failed with errors list
  end
```

| Step | Code path | Validation or check there |
|---|---|---|
| 2 | FE `pages/LoginPage.tsx` `signIn`, `app/deps.ts` `signIn`, `use-cases/sign-in.ts` | none: passes through |
| 3 | FE `adaptor/http/auth-gateway.ts` `signIn` | clears any old session so an old token is never sent with a login |
| 5 | FE `adaptor/http/client.ts` `send` | adds no bearer because the store is empty; 15 s timeout |
| 6 | BE `adaptor/http/auth.routes.ts` `POST /auth/login` | zod `LoginBody` in `adaptor/http/contract.ts`; failure is 400 `Validation failed` |
| 7-8 | BE `use-cases/auth.ts` `login`, `adaptor/supabase/auth-provider.ts` `signIn` | a new anon client per call so concurrent sign-ins never share state |
| 9-10 | BE `auth-provider.ts` `toSession` | no session is `not_authenticated`; `expiresAt` in epoch seconds |
| 11 | BE `app.ts` header middleware | `Cache-Control: no-store` on `/auth/*` and `/me` |
| 13-14 | FE `session-store.ts` `write`, `notify`; FE `lib/auth.tsx` `AuthProvider` | token change triggers `loadMe` |
| 17-19 | BE `adaptor/http/guard.ts` `requireAuth`, `use-cases/auth.ts` `authenticate`, `auth-provider.ts` `verify`, `profile` | bearer regex; Supabase rejects the token (4xx) or there is no profile row: 401 `not_authenticated` |
| 20 | BE `use-cases/auth.ts` `me` | reads the profile again for `fullName` |
| 23-26 | BE `auth-provider.ts` `authFailure`, `adaptor/http/error-handler.ts` `statusOf`, `adaptor/http/security-log.ts` `accessLog` | 4xx from Auth becomes `Invalid login credentials` (401) and one `login_failed` log line |
| 27-28 | FE `client.ts` `request` | a 401 with no stored session is unwrapped directly, never refreshed |
| 29-30 | BE `auth-provider.ts` `authFailure` | Auth 429 becomes `rate_limited` (429) |

## Authenticated request with automatic refresh

Any call made with an expired access token is refreshed once, shared by every parallel caller, and retried once; a dead refresh token signs the user out in every tab.

```mermaid
sequenceDiagram
  autonumber
  participant P as Page (two calls in parallel)
  participant C as client.ts
  participant S as session-store
  participant API as Express API
  participant GA as Supabase Auth
  participant T2 as Other tab

  P->>C: request A and request B
  C->>S: get() session
  C->>API: A and B with Bearer old token
  API-->>C: 401 not_authenticated (both)
  C->>S: get() latest
  alt another call or tab already rotated the token
    C->>API: retry with latest accessToken
  else token unchanged
    C->>C: refresh(): refreshing ??= one promise for A and B
    C->>API: POST /auth/refresh JSON refreshToken (no bearer)
    API->>API: RefreshBody.parse
    API->>GA: refreshSession (fresh anon client)
    alt refresh token valid
      GA-->>API: new session
      API-->>C: 200 data Session
      C->>S: set(new session)
      S-->>T2: storage event key seatsure.session, tab reads new token
      C->>API: retry A and B once with new token
      API-->>C: 200 data
      C-->>P: data
    else refresh token invalid or already used
      API-->>C: 401 not_authenticated
      C->>S: clear()
      S-->>T2: storage event, session null, tab shows login
      C-->>P: DomainError not_authenticated
    else throttled, 5xx or network error
      API-->>C: 429 rate_limited or 5xx
      C-->>P: DomainError, session kept for the next attempt
    end
  end
  opt retried request still answers 401
    C->>S: clear()
    C-->>P: DomainError not_authenticated
  end
```

| Step | Code path | Validation or check there |
|---|---|---|
| 2-4 | FE `adaptor/http/client.ts` `request`, `send` | bearer added from `store.get()`, which reads `localStorage` each time |
| 4 | BE `adaptor/http/guard.ts`, `auth-provider.ts` `verify` | expired or revoked token: 401 `not_authenticated` |
| 5-6 | FE `client.ts` `request` | if the stored token differs from the one sent, retry with it instead of refreshing |
| 7 | FE `client.ts` `refresh` | single flight: `refreshing ??=` shares one promise, reset in `finally` |
| 8-10 | BE `adaptor/http/auth.routes.ts` `POST /auth/refresh`, `auth-provider.ts` `refresh` | zod `RefreshBody`; Auth 4xx becomes `not_authenticated`, 429 becomes `rate_limited` |
| 13-14 | FE `session-store.ts` `write`, `storage` listener | other tabs get the `storage` event and re-read; `AuthProvider` reacts to the token |
| 15 | FE `client.ts` `request` | retried at most once |
| 18-21 | FE `client.ts` `signedOut` | any 4xx except 429 from refresh clears the session |
| 22-23 | FE `client.ts` `refresh` | 429, 5xx and network errors keep the session |
| 24-25 | FE `client.ts` `request` | a 401 after the retry clears the session |

## Logout

Signing out ends the session on the server and always clears the local tokens.

```mermaid
sequenceDiagram
  autonumber
  actor U as User
  participant SH as AppShell
  participant GW as auth-gateway
  participant C as client.ts
  participant S as session-store
  participant API as Express API
  participant GA as Supabase Auth
  participant AU as AuthProvider

  U->>SH: click sign-out button
  SH->>GW: signOut() via deps.ts
  opt a session is stored
    GW->>C: request POST /auth/logout
    C->>API: POST /auth/logout, Bearer accessToken
    API->>API: requireAuth() verifies the token
    API->>GA: admin.signOut(token, local) with service key
    GA-->>API: ok, or 4xx ignored
    API-->>C: 200 data null
  end
  Note over GW: any error (offline, expired) is swallowed
  GW->>S: clear() in finally
  S-->>AU: listener fires with null
  AU-->>SH: App renders the login routes, every path redirects to /
```

| Step | Code path | Validation or check there |
|---|---|---|
| 2 | FE `components/app-shell.tsx`, `use-cases/sign-out.ts` | none |
| 3-4 | FE `adaptor/http/auth-gateway.ts` `signOut` | calls the API only when a session exists |
| 5 | BE `adaptor/http/auth.routes.ts` `POST /auth/logout`, `requireAuth()` | 401 `not_authenticated` without a valid bearer (the client then tries one refresh) |
| 6-7 | BE `use-cases/auth.ts` `logout`, `auth-provider.ts` `signOut` | scope `local`: only this session ends; a 4xx from Auth (already gone) is ignored |
| 9 | FE `auth-gateway.ts` `signOut` | `finally` always clears the tokens |
| 10-11 | FE `lib/auth.tsx`, `App.tsx` | no session: only `/` (login) is routed |

## Book a seat

A parent books with a student name; `book_seat` runs as the parent and serialises bookings for the course on a row lock.

```mermaid
sequenceDiagram
  autonumber
  actor P as Parent
  participant FE as book-seat dialog
  participant API as Express API
  participant UC as bookings use case
  participant R as booking-repository
  participant RPC as book_seat (Postgres)

  P->>FE: choose course, type student name
  FE->>FE: bookSeat use case trims name
  FE->>API: POST /bookings JSON courseId, studentName, Bearer
  API->>API: requireAuth(), courseId must be a uuid
  API->>UC: bookSeat(actor, input)
  UC->>UC: trim, blank is student_name_required
  UC->>R: bookSeat(actor.token, courseId, name)
  R->>RPC: rpc book_seat as the user (anon key + token)
  RPC->>RPC: auth.uid() set, name not blank
  RPC->>RPC: select course FOR UPDATE (row lock)
  alt course missing
    RPC-->>API: course_not_found, 404
  else registration closed
    RPC-->>API: registration_closed, 400
  else seats taken >= capacity
    RPC-->>API: course_full, 400
  else account already holds or paid a seat
    RPC-->>API: unique index violation -> already_booked, 400
  else course pending, rejected or cancelled
    RPC-->>API: trigger -> course_not_approved, 400
  else seat free
    RPC->>RPC: expire stale holds, insert booking held, hold 7 days
    RPC-->>R: booking row
    R->>R: findBooking(id) with service key
    API-->>FE: 201 BookingDto with course, payments, proofs
  end
```

The race: 20 parents send `POST /bookings` for the last seat at the same moment
(`apps/backend/tests/integration/bookings-api.test.ts`, `r1-overbooking.test.ts`; k6 `tests/load/booking.js` does it with 10).

```mermaid
sequenceDiagram
  autonumber
  participant P1 as Parent 1
  participant P2 as Parents 2 to 20
  participant API as Express API
  participant DB as Postgres courses row

  par all at once
    P1->>API: POST /bookings
  and
    P2->>API: POST /bookings (19 requests)
  end
  API->>DB: 20 book_seat calls
  DB->>DB: first transaction takes FOR UPDATE on the course row
  Note over DB: the other 19 wait on the lock
  DB-->>API: first: count 0 < 1, insert, commit, lock released
  API-->>P1: 201
  loop each waiting transaction in turn
    DB->>DB: takes the lock, counts 1 seat taken
    DB-->>API: raise course_full
    API-->>P2: 400 course_full
  end
  Note over DB: seats_taken ends at exactly 1
```

| 4 | BE `adaptor/http/bookings.routes.ts` `POST /bookings`, `BookSeatInput` | `requireAuth()` (any role); `courseId` uuid via zod, else 400 `Validation failed` |

## Upload a transfer proof and confirm payment

The parent uploads the image as a raw body, then confirms; `confirm_transfer_payment` writes one payment with a receipt and is safe to repeat.

```mermaid
sequenceDiagram
  autonumber
  actor P as Parent
  participant FE as MyBookingsPage
  participant API as Express API
  participant UC as payments use case
  participant R as payment-repository
  participant ST as Storage payment-proofs
  participant DB as Postgres

  P->>FE: choose image file
  FE->>FE: submitPaymentProof: jpeg, png or webp, max 5 MiB
  FE->>API: PUT /bookings/:id/proof, Content-Type image/png, raw bytes, Bearer
  API->>API: requireAuth() before the body is read
  API->>API: express.raw limit 5mb
  alt body over 5 MiB
    API-->>FE: 413 proof_size_exceeded
  end
  API->>UC: submitProof(actor, uuid id, type, bytes)
  UC->>UC: proof_type_invalid, payment_proof_required (empty)
  UC->>R: ownBooking(actor, id) as user
  alt not found or not owner
    API-->>FE: 404 booking_not_found
  else status is not held
    API-->>FE: 400 booking_not_payable
  end
  UC->>ST: upload (user id)/(booking id)-(uuid).png as user
  UC->>R: proofOf(actor, id)
  alt first proof
    R->>DB: insert payment_proofs (RLS: own held booking)
  else replacing a proof
    R->>DB: update proof_path, submitted_at (RLS: still held)
    UC->>ST: remove old object (best effort)
  end
  opt recording fails
    UC->>ST: remove the new object, rethrow
  end
  API-->>FE: 200 data null

  P->>FE: confirm payment
  FE->>API: POST /bookings/:id/confirm-payment, Bearer
  API->>R: confirmTransfer -> rpc confirm_transfer_payment as user
  R->>DB: read booking where user_id = auth.uid()
  DB->>DB: lock course FOR UPDATE, then booking FOR UPDATE
  alt already paid
    DB-->>API: return, no second payment
  else not held
    DB-->>API: booking_not_payable
  else course cancelled
    DB-->>API: course_cancelled
  else no proof row or object
    DB-->>API: payment_proof_required
  else held with proof
    DB->>DB: booking paid, paid_at now
    DB->>DB: insert payment, key transfer-proof-(proof id), receipt RC-YYYYMMDD-nnnnnn
  end
  API-->>FE: 200 data null, or 400 with the code
  FE->>API: GET /bookings/mine (reload), receipt page GET /bookings/:id
```

| Step | Code path | Validation or check there |
|---|---|---|
| 2 | FE `use-cases/submit-payment-proof.ts` `createSubmitPaymentProof` | type and size (convenience; the server repeats both) |
| 3 | FE `adaptor/http/payments-gateway.ts` `submitProof`, `client.ts` `send` | a `Blob` goes as the raw body with its own `content-type` |
| 4 | BE `adaptor/http/payments.routes.ts` `router.put(..., requireAuth(), proofBody, submitProof, proofTooLarge)` | auth runs first: no token is 401 before any bytes are parsed |
| 5-6 | BE `payments.routes.ts` `proofBody`, `proofTooLarge` | `express.raw` reads only the three image types; over 5 MiB is 413 `proof_size_exceeded` |
| 7 | BE `payments.routes.ts` `bookingId` | non-uuid id is 404 `booking_not_found` |
| 8 | BE `use-cases/payments.ts` `submitProof`, `entities/payment.ts` | `proof_type_invalid` (400), empty is `payment_proof_required` (400), over `MAX_PROOF_BYTES` is 413 |
| 9-11 | BE `adaptor/supabase/payment-repository.ts` `ownBooking` | user-token read filtered by `user_id`; `booking_not_found`, `booking_not_payable` |
| 12 | BE `adaptor/supabase/proof-storage.ts` `upload`; SQL storage policies | bucket limit 5 MiB and MIME list; first folder must equal `auth.uid()` |
| 13-14 | BE `payment-repository.ts` `insertProof`; SQL policy "parents submit own transfer proofs" | booking owned and `held` |
| 15-16 | BE `payment-repository.ts` `replaceProof`; SQL policy "parents replace own unconfirmed transfer proofs" | no row updated is `booking_not_payable`; old object removed quietly |
| 17 | BE `use-cases/payments.ts` `submitProof` `catch` | new object removed so no orphan stays |
| 19-20 | FE `use-cases/submit-payment-proof.ts` `createConfirmPaymentProof`, `payments-gateway.ts` `confirm` | none |
| 20-21 | BE `payments.routes.ts` `POST /bookings/:id/confirm-payment`, `use-cases/payments.ts` `confirmPayment`, `payment-repository.ts` `confirmTransfer` | `requireAuth()`; uuid id; user token so `auth.uid()` is the parent |
| 22-23 | SQL `20261016000000_confirm_locks_course.sql` `confirm_transfer_payment` | ownership; course lock then booking lock, the same order as `cancel_course` and `book_seat` |
| 24-27 | SQL `confirm_transfer_payment` | idempotent once paid; `booking_not_payable`, `course_cancelled`, `payment_proof_required` (path prefix and object must exist) |
| 28-29 | SQL `confirm_transfer_payment`; unique `payments.idempotency_key` | one payment per proof even under parallel confirms (`apps/backend/tests/integration/r2-payment.test.ts`) |

## Cancel a course with paid bookings

An admin cancels a course; one SQL function closes it, reports a refund for each paid booking and cancels the bookings, and the payments overview shows the refunds.

```mermaid
sequenceDiagram
  autonumber
  actor A as Admin
  participant FE as AdminPage
  participant API as Express API
  participant UC as courses use case
  participant R as course-repository
  participant DB as cancel_course (Postgres)
  participant PR as payment-repository

  A->>FE: cancel course, enter reason
  FE->>API: POST /courses/:id/cancel JSON reason, Bearer
  API->>API: requireAuth admin, auditCourseAction course_cancel, uuid id, CancelCourseBody
  API->>UC: cancelCourse(actor, id, reason)
  UC->>UC: role admin, trimmed reason not blank
  UC->>R: cancel(actor, id, reason)
  R->>DB: rpc cancel_course as user
  DB->>DB: is_admin() else admin_required (sent as forbidden)
  DB->>DB: lock course FOR UPDATE
  alt missing
    DB-->>API: course_not_found, 404
  else already cancelled
```

## Request pipeline inside the API

Every request passes the same middleware in `app.ts`; errors from any step end in `errorHandler` and leave in the envelope.

```mermaid
flowchart TD
  req["HTTP request"] --> al["accessLog<br/>registers a finish hook"]
  al --> hd["headers middleware<br/>nosniff, no-store on /auth/* and /me"]
  hd --> cors["cors<br/>allow only FRONTEND_ORIGIN"]
  cors --> json["express.json"]
  json -->|"malformed JSON"| eh
  json --> match{"route matches?"}
  match -->|"no"| nf["404 Not found"]
  match -->|"GET /health"| health["200 ok true"]
  match -->|"yes"| ra["requireAuth(roles)<br/>bearer, verify, profile, role"]
  ra -->|"401 or 403"| eh
  ra --> audit["auditCourseAction<br/>admin course routes only"]
  audit --> raw["express.raw 5mb<br/>PUT /bookings/:id/proof only"]
  raw --> handler["handler<br/>uuid path id, zod parse"]
  handler -->|"ZodError"| eh
  handler --> uc["use case<br/>rules, DomainError"]
  uc --> ad["adaptor/supabase<br/>P0001 -> DomainError"]
  ad --> ok["res.json success true, data"]
  uc -->|"DomainError"| eh
  ad -->|"Error"| eh
  eh["errorHandler<br/>DomainError -> statusOf<br/>ZodError -> 400 Validation failed<br/>parse failed -> 400 Invalid JSON body<br/>other 4xx kept, else 500"]
  eh --> out["response success false, message, errors?"]
  ok --> fin["finish: accessLog logs 401 and 403,<br/>auditCourseAction logs admin_action"]
  out --> fin
  nf --> fin
```

| Step | Code path | Validation or check there |
|---|---|---|
| accessLog | BE `adaptor/http/security-log.ts` `accessLog` | on finish: `login_failed` for `POST /auth/login` 401, else `unauthorized` or `forbidden` with the route pattern |
| headers | BE `app.ts` | `X-Content-Type-Options: nosniff`; `Cache-Control: no-store` when the path matches `NO_STORE`; `x-powered-by` disabled |
| cors | BE `app.ts` `cors({ origin })` | only `FRONTEND_ORIGIN` gets CORS headers |
| json | BE `app.ts` `express.json()` | malformed JSON is `entity.parse.failed`, 400 `Invalid JSON body` |
| requireAuth | BE `adaptor/http/guard.ts` | `Bearer` regex, `authenticate`, role list; sets `req.actor` before the role check |
| audit | BE `security-log.ts` `auditCourseAction` | only for actors with role admin, on PATCH, approval and cancel routes |
| raw | BE `payments.routes.ts` `proofBody` | only the three image types, 5 MiB |
| handler | BE `*.routes.ts` | `courseId`, `bookingId` uuid checks; zod schemas from `contract.ts` |
| use case | BE `use-cases/*.ts` | business rules, `DomainError(code)` |
| adaptor | BE `adaptor/supabase/*.ts` | known SQL codes become `DomainError`; anything else an `Error` without the database message |
| errorHandler | BE `adaptor/http/error-handler.ts` | `statusOf`: 401, 403, 404 for `*_not_found`, 409 `course_not_pending`, 429, else 400; 500 `Internal server error` |
| 404 | BE `app.ts` | unknown route is `404 Not found` |
