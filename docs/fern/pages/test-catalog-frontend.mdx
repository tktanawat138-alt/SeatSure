Everything under `apps/frontend/tests/` runs with Vitest in a `node` environment: no browser, no React renderer, no real
network, no `.env.local`. [Testing](/testing) explains the levels and the rules; this page lists the tests themselves.
The project-level suites (cross-app integration, Playwright, k6) are in [Project test catalog](/test-catalog-project).

## Unit tests

### `unit/layering.test.ts` (5 tests)

How it scans: it walks `apps/frontend/src/<layer>/` recursively, reads every `.ts` and `.tsx` file as text, extracts every
`from '...'` import with a regex and fails when an import equals, or starts with, a forbidden prefix. The failure message
names the file and the boundary. A layer folder that does not exist is skipped (an empty list), so adding a layer later
does not break the test.

| Test name | Input / setup | What is validated / expected | Layer |
|---|---|---|---|
| entities imports nothing from an outer layer | all files under `src/entities/`; banned: `react`, `@supabase`, `@/interfaces`, `@/use-cases`, `@/adaptor`, `@/ui` | no file imports any banned prefix | entities |
| interfaces imports nothing from an outer layer | all files under `src/interfaces/`; banned: `react`, `@supabase`, `@/use-cases`, `@/adaptor`, `@/ui` | no banned import | interfaces |
| use-cases imports nothing from an outer layer | all files under `src/use-cases/`; banned: `react`, `@supabase`, `@/adaptor`, `@/ui` | no banned import | use-cases |
| adaptor imports nothing from an outer layer | all files under `src/adaptor/`; banned: `react`, `@/use-cases`, `@/ui` | no banned import | adaptor |
| nothing under src imports @supabase or @/lib/supabase | every `.ts` and `.tsx` file under `src/` | no import starting with `@supabase` and no import of `@/lib/supabase`: the browser talks only to the API | source tree |

### `unit/styles.test.ts` (1 test)

How it scans: it walks all of `src/` for `.tsx` files, skips `src/components/ui/` (shadcn owns its inline `cva`), and
tests each remaining file's source with three regexes. The first offending file fails the assertion and is named in the
message. `.styles.ts` files are not scanned here (see the next file).

| Test name | Input / setup | What is validated / expected | Layer |
|---|---|---|---|
| has no literal className strings, cn() or style props outside components/ui | every `.tsx` under `src/` except `src/components/ui/` | no match for `className="..."`, `className='...'`, `className={"..."}` (a quote or backtick right after the brace), no `cn(` call, no `style={{`. Passing `className={card({ tone })}` is allowed | source tree |

## Integration tests (stubbed network)

All four files use the real HTTP adaptors (`client.ts`, `session-store.ts`, the gateways) and the real use cases. Only
`fetch` is replaced.

### The stub: `integration/stub-network.ts`

Not a test file; it is the fake network.

| Helper | Behaviour |
|---|---|
| `stubNetwork(...routes)` | replaces the global `fetch` with `vi.fn`; records every call as `{ url, init }` and returns that array; the first route that answers wins; an unmatched request throws `unexpected request: <path>`; every reply is a JSON `Response` with the given `status` (default 200) |
| `api(method, path, reply)` | a route that matches `url.pathname` and the HTTP method (default `GET`); `reply` is `{ status, body }` or a function of the request init, so a test can answer by its `Authorization` header |
| `authorization(init)` | the `Authorization` header a stubbed request carried, or `null` |

Each file sets `VITE_API_URL=http://api.test` through `vite.config.ts`, builds its own `createApiClient({ baseUrl })` and an
in-memory `Storage` for the session store, and calls `vi.unstubAllGlobals()` after each test. The shared envelope helpers are
`ok(data)` for `{ success: true, data }` and `fail(status, message)` for `{ success: false, message }`.

## Gaps

- **No React component or hook tests.** Vitest runs with `environment: 'node'`; there is no jsdom or Testing Library. Pages,
  feature components, `ThemeProvider`, `useTheme`, `useAutoRefresh` (the hook, as opposed to `createAutoRefresh`) and
  the route guard are exercised only by Playwright ([Project test catalog](/test-catalog-project)). A render bug that the
  specs do not walk through is not caught by any unit test.
- **Pages are covered only by e2e, and some flows by nothing.** The specs never open `PaymentsPage` (the payment system and refund
  report view), reject a course (`ปฏิเสธ` in the approval queue), open the roster dialog, edit a course schedule as a teacher, or
  change capacity and registration from the admin table. Receipt and booking pages are covered through one happy path.
- **`src/lib/format.ts` is tested only for `errorText`.** `baht`, `dateTime`, `courseSchedule`, `parentCourseSchedule`,
  `holdIsLive`, `holdsSeat`, `bookingStatus` and `countdown` have no unit test.
- **14 of the 23 `errorText` messages have no unit test** (table above); a typo in one of them is not caught.
- **Use cases without a direct unit test:** `loadMyBookings`, `loadBooking`, `loadActiveBookings`, `loadCourseRoster`
  and `bookSeat` are exercised only through the gateway integration tests (with the real gateway, not a fake port).
- **Static rules cover only what the regexes see.** The styling test matches literal `className="..."`; a class string
  built in a variable, a template literal with `${}`, or `className={cond ? 'a' : 'b'}` is not flagged. The dark-variant test
  skips template literals with interpolation and the palette families it does not list.
- **No test of the built bundle.** `npm run build` (typecheck and Vite build) runs in CI next to the unit tests, but nothing
  asserts the bundle content, for example that no service key is inlined.
