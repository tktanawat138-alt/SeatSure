# Courses group (Task 4), 2026-10-10

## What was built

Backend (`apps/backend`)
- `entities/course.ts`: `Course` (same fields as `CourseDto`), `NewCourse`, `isSchoolAdmin` (role admin and email `admin01@seatsure.test`), `endsAfterStarts`.
- `interfaces/course-repository.ts`: the `CourseRepository` port. Reads are plain lookups; writes take the actor because the database guards decide by the signed-in user.
- `use-cases/courses.ts`: `createCourses(repo)` returns `listCourses`, `createCourse`, `updateCourse`, `reviewCourse`, `cancelCourse`.
- `adaptor/supabase/course-repository.ts`: reads with the service-role client, writes (insert, update, `cancel_course` RPC) with a user-scoped client (anon key plus the actor's bearer token, no session persistence), so RLS, `guard_course_capacity`, `guard_course_approval` and `is_admin()` run as that user.
- `adaptor/http/courses.routes.ts`, `adaptor/http/endpoints/courses.ts` (docs registry, five operations).
- Tests: `tests/unit/use-cases/courses.test.ts`, `tests/unit/api/courses.test.ts`, `tests/integration/courses-api.test.ts`, fake in `tests/unit/courses-fake-repository.ts`.

Frontend (`apps/frontend`)
- `interfaces/courses-gateway.ts`, `adaptor/http/courses-gateway.ts`, use cases `list-courses`, `create-course`, `update-course`, `review-course`, `cancel-course`, and `update-course-schedule` now goes through the HTTP gateway. The old supabase `course-schedule-gateway` and its interface were removed. `app/deps.ts` exports `listCourses`, `createCourse`, `updateCourse`, `reviewCourse`, `cancelCourse`. Pages are not migrated (Task 8).

## Routes

| Route | Who | Notes |
|---|---|---|
| `GET /courses` | any signed-in | `?pending=true` (admin) approval queue, `?mine=true` own courses |
| `POST /courses` | teacher | created `pending`, `registration_open=false` |
| `PATCH /courses/:id` | admin (capacity, registrationOpen), teacher (own schedule) | returns the course |
| `POST /courses/:id/approval` | admin01 | approve opens registration |
| `POST /courses/:id/cancel` | admin | `data` is the refund count (a number) |

## Decisions

- Listing: parent gets approved and not cancelled (the old Courses page filtered cancelled client-side; the API now does it). Teacher gets every course of their own whatever its status, cancelled ones included (TeacherPage hid cancelled ones client-side; Task 8 should keep that filter). Admin gets approved courses including cancelled (what `course_seats` showed), plus the pending queue on request. Rejected courses are only visible to their teacher.
- `seats_taken` and `teacher_name` are now filled for pending queue and teacher lists (the pages used 0/null placeholders). Pending and rejected courses have `seats_taken=0` since bookings require approval.
- `admin01_required` maps to HTTP 403 (added to `error-handler.ts`). `forbidden` stays 403, `course_not_found` 404. A path id that is not a uuid is `course_not_found` (404), not a validation error.
- Approval and cancel routes are guarded by role `admin`; non-admin roles get `forbidden`, an admin who is not admin01 gets `admin01_required` on approval. Cancel returns the bare count as `data`, no contract schema was added.
- An admin may not change the schedule and a teacher may not change capacity or registration (brief); these are `forbidden`, before the course lookup so existence is not leaked.
- `course_cancelled` is raised by the use case when reopening a cancelled course, and also mapped from the database trigger. `capacity_below_booked` comes only from the trigger. SQL `raise exception` messages (`P0001`) become `DomainError(message)`, `admin_required` and `teachers_may_only_change_schedule` become `forbidden`, RLS `42501` becomes `forbidden`, an update that touches no row becomes `forbidden`.
- Dates come back in PostgREST format (`2026-12-01T09:00:00+00:00`), the same as the old direct reads, so the UI date code is unchanged.

## Caveats

- Every route group adds a required port to `AppDeps` (`courseRepository` here), so existing tests that call `createApp({ frontendOrigin, authProvider })` fail `tsc --noEmit` with TS2739 (they run fine, the ports are only touched by the courses routes). A shared test helper for a full fake `AppDeps` would fix it; not done here because the files are shared.
- Integration tests create courses through the API with the title prefix `API test` and delete them (and their `refund_reports`) in `afterAll`.
- `docs/fern/openapi/openapi.json` must be regenerated (`task docs:openapi`) once the endpoints land; the docs group owns that.
